# Agentic Engineering 회고 — Vibe MVP에서 "스스로 굴러가는 시스템"으로

> 이 문서는 이 프로젝트의 **개발 과정 회고**다. 코드의 "어떻게"(`architecture.md`)나 결정의 "왜"(`decisions.md`)와 달리,
> **"순수 프롬프트 챗으로 만든 MVP에, Agentic Engineering을 얹으니 무엇이 어떻게 좋아졌나"**를 비개발자도 알 수 있게 정리한 것이다.
> 학습·인수인계용 교육 문서이며, 새 ADR(되돌리기 어려운 결정)이 아니다.

마지막 업데이트: 2026-06-04

---

## 0. 한 문장 요약

- **Before**: AI에게 **매번 잘 부탁하기** (사람의 기억과 주의력에 의존하는 *대화*).
- **After**: AI가 **잘할 수밖에 없는 환경을 코드에 박아두기** (규칙·기억·자동검사·피드백 루프가 들어간 *시스템*).

좋아진 것은 "앱 기능"이 아니라 **"AI를 다루는 작업 방식"**이다. 품질의 책임이 *사람*에게서 *시스템*으로 옮겨갔다.

> **오늘 한 일의 본질**: 순수 챗으로 단일 `index.html` MVP를 만든 뒤, 그 위에 `CLAUDE.md` · `docs`(architecture/ADR) · `hooks` · `tests/guardrails` · `.agent-rules.md`를 얹어 작업 시스템으로 진화시켰다.

## 1. 큰 그림 — Before / After

| | **Before (Vibe 코딩 MVP)** | **After (Agentic Engineering)** |
|---|---|---|
| AI의 기억 | 매 채팅마다 **백지에서 시작** | `CLAUDE.md`가 매 세션 자동 로드 → 규칙 알고 시작 |
| 규칙의 위치 | 사람 머릿속에만 | 문서·테스트·룰 파일로 **외부화** |
| 실수 감지 | 사람이 눈으로 발견할 때만 | 커밋 때 **자동 검사**가 잡아서 되먹임 |
| 일관성 | 부탁할 때마다 패턴이 흔들림 | "한 가지 일 = 한 가지 방법" 고정 |
| 결정의 이유 | 시간 지나면 아무도 기억 못 함 | ADR에 "왜"가 박제됨 |
| 누가 운전 가능? | 전체 맥락 아는 **본인만** | 새 AI 세션·다른 사람도 레일 위에서 가능 |

## 2. 무엇이, 어떻게 좋아졌나 (8가지 축)

각 축은 **Before → After + 이 프로젝트의 실제 예시 + 일상 비유**로 정리했다.

### ① AI가 더 이상 "기억상실증"에 안 걸린다 — `CLAUDE.md`
- **Before**: 새 채팅마다 "프레임워크 쓰지 마", "단일 파일 유지", "localStorage 직접 부르지 마"를 **매번 다시 설명**해야 했다. 안 하면 AI가 모르고 어겼다.
- **After**: `CLAUDE.md`가 세션 시작 시 자동 로드된다. AI가 이미 규칙을 **알고** 시작한다.
- 🧱 비유: 새 알바생이 올 때마다 가게 규칙을 처음부터 설명하던 걸 → **벽에 붙은 업무 매뉴얼**로 바꾼 것. (비개발자가 체감하는 가장 큰 변화 — 사람이 "기억 장치" 노릇을 그만둬도 된다.)

### ② AI의 "변덕(variance)"이 줄었다 — `.agent-rules.md`(50% 룰)
- **Before**: 월요일엔 A 방식, 금요일엔 비슷한 걸 B 방식으로. 날짜 만드는 법 두 가지, 저장하는 법 두 가지로 **갈라지며 코드가 어질러짐**.
- **After**: "localStorage는 `Store`로만", "날짜는 `DateUtil.toKey()`로만" 식으로 **blessed 경로 하나만** 못박았다. AI가 매번 같은 선택을 한다.
- 🧱 비유: 주방마다 다른 레시피로 요리하던 걸 → **표준 레시피북** 하나로 통일. 같은 재료를 두 번 부탁해도 같은 맛.

### ③ 실수를 사람이 아니라 기계가 먼저 잡는다 — `tests/guardrails.test.js` + 커밋 후 훅
- **Before**: AI가 절대 규칙을 깨도(외부 CDN 추가, `toISOString` 사용 등) **아무도 안 막았다**. 운 나쁘면 자정 근처 하루 어긋남 버그나 API 키 노출로 **나중에야** 터진다.
- **After**: 커밋하면 가드레일 테스트가 **자동 실행**되고, 위반이면 빨간불 → 그 출력이 AI에게 되돌아가 **스스로 고친다**(ADR-005).
- 🧱 비유: 맞춤법 검사기 / 화재경보기. 사람이 일일이 검사 안 해도 알아서 울린다. ("기계가 기계를 감시")

### ④ 빠뜨리던 코드 리뷰가 강제된다 — 커밋 전 리뷰 훅
- **Before**: "리뷰는 나중에 해야지" → **결국 안 함**. 실수가 그대로 들어간다.
- **After**: 커밋 직전에 변경분(diff)을 AI가 **반드시 한 번 리뷰**하게 막아둔다(ADR-006). 자동이라 잊을 수가 없다.
- 🧱 비유: 출고 전 **검수 도장** 없이는 물건이 못 나가게 한 것.

### ⑤ "왜 이렇게 만들었는지"가 박제된다 — ADR(`decisions.md`)
- **Before**: "API 키를 왜 브라우저에 뒀지?"(ADR-003), "날짜를 왜 이상하게 만들지?"(ADR-004) → 몇 달 뒤엔 **아무도 기억 못 해서**, 누가 "고친다"며 건드렸다가 **버그를 되살린다**.
- **After**: ADR에 *이유·포기한 대안·트레이드오프*가 적혀 있다. 미래의 자신(또는 AI)이 **같은 실수를 반복하지 않는다**.
- 🧱 비유: "이 벽은 내력벽이라 부수면 안 됨"이라고 **도면에 표시**해 둔 것.

### ⑥ 시스템이 스스로 교정한다 (self-correction 루프)
- **Before**: 피드백 루프가 **사람 한 명**뿐. 사람이 못 잡으면 끝.
- **After**: 테스트 실패·diff가 훅을 통해 AI 컨텍스트로 **되돌아가** AI가 자기수정. 감시 부담이 줄어든다.
- 🧱 비유: 자동온도조절기(thermostat). 사람이 계속 안 봐도 알아서 맞춘다.

### ⑦ 본인 말고 다른 사람/세션도 운전할 수 있다 (확장성·인수인계)
- **Before**: 전체 맥락이 **사람 머릿속**에 있어서, 사실상 본인만 안전하게 작업 지시 가능.
- **After**: 지식이 **저장소(repo) 안**에 있다. 새 AI 세션도, 다른 협업자도 레일 위에서 작업 가능.
- 🧱 비유: 사장님 머릿속 노하우 → **운영 매뉴얼화**. 가게가 사장 없이도 돌아간다.

### ⑧ 신뢰가 쌓여 속도가 붙는다
- **Before**: 안전망이 없으니 **모든 걸 꼼꼼히 검토**해야 해서 느리다.
- **After**: 루틴한 변경엔 자동 가드레일이 있으니, 사람은 *중요한 판단*에만 집중하고 나머진 빠르게 진행한다.

## 4. 솔직한 트레이드오프 (항상 정답은 아니다)

- 이 장치들은 **선투자 비용**이 든다(문서·훅·테스트 작성). 커밋마다 리뷰 왕복이 한 번 더 생겨 **약간 느려진다**.
- **버리고 말 1회용 MVP라면 오버킬**이다. 가치는 프로젝트가 **오래 살아남을수록 / 세션이 많아질수록 / 사람이 늘수록 복리로** 커진다.
- 그래서 이 작은 앱에 이걸 다 얹은 진짜 이유는 "이 앱에 꼭 필요해서"가 아니라 **Agentic Engineering 자체를 몸으로 익히는 실습**이라는 데 있다. (작은 앱이라 전체를 눈으로 볼 수 있어 학습용으론 오히려 이상적이다.)
